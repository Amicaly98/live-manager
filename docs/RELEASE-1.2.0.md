# 1.2.0

桌面版沿用原来的应用身份和数据目录，接入服务器版截至 `954c33a` 的相关核心更新。没有加入服务器的多实例管理控制台。

- 首页新增“容错时长”，原紧迫率保留参考。按每天 22 小时、任务尽量靠近截止日执行的模型，比较各截止点的累计容量余量；当天执行进度不改变基线，计划改变及跨日时重算。完整公式和“余量充足”条件见 [README](../README.md#容错时长到截止日还剩多少容量)。
- 同步分区缓存、分区失效、人脸确认、轮转及任务读取的相关修复。推流来源由设置统一决定，FFmpeg 中断不等于平台下播，已确认的进度不会因此归零。
- 同步紧凑的任务列表和小屏布局，首页可向下滚动查看更大的日志区域。通知设置按当前事件职责说明，列出实际邮件主题；不再显示已失效的重连次数设置。
- 保留桌面手动恢复：重新打开应用不会自动开播；继续场次沿用原身份、目标和检查点。任务创建的未知结果继续按原账号、原令牌核对，多条待核对操作互不覆盖。
- 保留单实例与账号占用保护，以及“停止并退出 / 不停止并退出”的两种行为。退出未确认时保留窗口和后端，允许重试。
- 包含此前未正式发布的安装升级保护：旧安装目录资料在旧版卸载之前保全；无法确认停写或完整复制时中止升级，原资料和已有保全不被半份副本覆盖。
- 修复检查更新误报有更新、下载完成显示旧版本号的问题。

Windows 安装版与便携版均内置后端，无需安装 Python；使用 FFmpeg 推流仍需自行准备 FFmpeg。安装版升级保持原应用身份；不要为了升级手动删除用户数据目录。

本次验证使用隔离账号目录、回环平台和本地媒体输出。真实 B 站、SMTP/Server酱投递、公开更新下载后的自动安装、macOS/Linux 和代码签名不在本次验证结论内。
